## Context

Credentials had accumulated in source repos and deployment config over years: database passwords, API keys, tokens.

## Design

- **Discovery:** scan every repository with **gitleaks**, then a second **entropy-based pass** to catch secrets the default rules miss.
- **Remediation:**
  - Replace each secret with a `${placeholder}` in service config and an encrypted variable in **Ansible Vault**, or move it to **AWS Secrets Manager**.
  - Keep the service repo, Ansible v1 and Ansible v2 in parity, so no environment breaks.
  - Ship one PR per service.
- **Tracking & handoff:** a central tracker of every secret, its new home and its status, handed to DevOps for rotation. Removing a secret from the latest commit does not un-leak it; rotation does.
- **Team:** split by domain groups, with a shared playbook and review checklist, and daily status on the tracker.

## Key decisions & trade-offs

<Callout variant="tradeoff" title="Rotation over history rewrites">Rewriting git history is disruptive and incomplete (forks, clones). Rotating the credential makes the leaked value useless.</Callout>

<Callout variant="tradeoff" title="Parity checks before merge">Most outage risk in secret migration comes from config drift between deployment sources, so parity was checked on every PR.</Callout>

## Results

- Hardcoded secrets removed across the organization's services, SDKs, infra and mobile repos, with **zero production impact**.
- A repeatable process: tracker + playbook + rotation handoff.

## What I'd do next

pre-commit and CI secret scanning on every repo, and short-lived credentials (for example IAM database auth) wherever possible.
