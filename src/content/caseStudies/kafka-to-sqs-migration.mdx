## Context

Our services published domain events (payment reconciliation, transaction conveyance, credit and charge calculations, order status) on an in-house Kafka-based event bus. The organization standardized on AWS SQS/SNS: SQS for point-to-point work queues, SNS for fan-out.

## The problem

These are money-moving events. A lost or reordered message can mean an unreconciled payment or a wrong interest calculation. The migration had to happen live, stream by stream, with instant rollback and without changing consumer behavior.

## Design

- **Per-event traffic split.** Each event has a config key for the percentage of traffic sent to SQS. The producer rolls a random number per publish: below the threshold goes to SQS, otherwise to Kafka.
- **SQS-first with automatic fallback.** If an SQS publish throws, the same event is published to Kafka in the catch block. No event is dropped because the new path failed.
- **Canary ramp.** Start at 10–20%, watch consumer success, queue depth and fallback counts, then ramp to 100%. Remove the split and fallback in a separate cleanup PR.
- **Config-only rollback.** The percentages live in Ansible-managed config, so rolling back is a config change and restart, not a code deploy.
- **Ordering where it matters.** Events that must be processed in order use **SQS FIFO queues with message-group ids**, per credit line or per order, with deduplication ids. Other streams stay on standard queues for throughput.
- **Consumer compatibility.** Consumers receive messages through a Lambda-to-HTTP bridge that calls their existing endpoints. The legacy idempotency, group and transaction-id headers are carried over, so consumers run unchanged.
- **Naming convention:** `<Env>_<Producer>_<Consumer>_<Event>_<UseCase>[.fifo]`.

## Key decisions & trade-offs

<Callout variant="tradeoff" title="Fallback at the call site">It's simple and explicit, and the trade-off is a little duplicated logic per event, which is why the cleanup PR matters.</Callout>

<Callout variant="lesson" title="The payload-contract bug">One stream published a bare JSON array on SQS while consumers expected an object. We fixed the consumer contract to accept an object wrapper and aligned both transports. Lesson: treat the transport switch as a contract change and test with real payloads.</Callout>

<Callout variant="tradeoff" title="FIFO only where needed">FIFO caps throughput per message group, so it is reserved for streams where order changes the result.</Callout>

## Results

- The reconciliation pipeline (**~800K messages/month**) runs on SQS at **99.94%** consumer success.
- Payment and credit streams migrated with **zero downtime** and a **config-only rollback** path.

## What I'd do next

- Use deterministic idempotency keys on every stream.
- Keep dead-letter queue (DLQ) and visibility-timeout settings in infrastructure-as-code next to the code.
- Add a transactional outbox so events publish only after the DB commit.
